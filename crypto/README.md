# ArcTrade 크립토 — 통계적 차익거래 (Avellaneda-Lee)

CryptoBars 아카이브(1,057종목 · 1분봉 · 2023-01-01~ · **상장폐지 포함**) 위에서 도는
잔차 평균회귀 롱숏. KRX 판(`../core/`)과 코드가 분리돼 있고, 공유하는 건 OU 수학 하나뿐이다.

## KRX 판과 무엇이 다른가

| | KRX (`core/`) | 크립토 (`crypto/`) |
|---|---|---|
| 시장시간 | 09:01~15:19, 일 경계·동시호가 제외 | **24/7, 경계 없음** |
| 팩터 | KOSPI·KOSDAQ 등가중평균 2팩터 | **고유포트폴리오** (지수도 업종분류도 없다) |
| 3번째 팩터 | 업종 동시점 평균 | **클러스터 동시점 평균** (가격에서 발견한 섹터) |
| 방향 | 현물이라 롱온리 | perp 이라 **롱숏 달러중립** |
| 시간 단위 | 분 | **봉** (`CRY_BAR_MIN` 로 바꿈) |
| 부실 게이트 | DART 재무 | 유동성·가짜유동성 스크리닝 |

## 구성

| 파일 | 역할 |
|---|---|
| `data.py` | CryptoBars 아카이브 → 가격·거래대금 패널(캐시). `live_bars` 는 실시간 저장소 |
| `screen.py` | 유동성·마찰·가짜유동성 필터 (Amihud · Corwin-Schultz · wash_z) |
| `factors.py` | 고유포트폴리오 잔차화 + Marchenko-Pastur 상관행렬 정제 |
| `cluster.py` | 전수 상관 → 클러스터링 → **창간 안정성 검증** (CLI) |
| `engine.py` | s-score 스냅샷. 라이브·백테스트 공용 |
| `backtest.py` | 워크포워드. 클러스터를 창마다 다시 적합해 lookahead 차단 |
| `live.py` | 24/7 루프 (모의장부 전용) |
| `test_crypto.py` | 자체점검 11건, 네트워크 없이 돎 |

## 실행

```bash
V=.venv/bin/python   # duckdb·sklearn이 설치된 가상환경

$V -m crypto.cluster --report      # 스크리닝 분포 (문턱 정하기 전에)
$V -m crypto.cluster               # 전수 클러스터링 + 안정성 → data/crypto/
$V -m crypto.backtest --ablation   # 워크포워드 (3년 ~4시간)
$V -m crypto.sweep_run             # 손익분기 비용 격자
$V -m crypto.live --once           # 라이브 1사이클 (모의)
$V -m crypto.test_crypto           # 자체점검
```

산출물은 전부 `../data/crypto/` 에 떨어진다 — `clusters.csv` `pairs.csv` `stability.json`
`bars_{15,60}m.parquet`(캐시) `paper_{trades.csv,positions.json}`.

## 백테스트 실측 (2026-08-07)

비용을 0 으로 두고 돌리면 **거래당 총이익(bp) = 손익분기 왕복비용**이다.
참고선: 바이낸스 USDⓈ-M 테이커 왕복 10bp · 메이커 왕복 4bp. 2026-02-01~08-06.

| 설정 | 거래 | 손익분기 비용 | 평균보유 | 승률 |
|---|--:|--:|--:|--:|
| s1.25 · 창24h · 1시간마다 | 64,016 | 1.40bp | 2.8h | 51.1% |
| **s2.50 · 창24h · 1시간마다** | 1,722 | **10.14bp** | 2.8h | 53.0% |
| s1.25 · 창72h · 4시간마다 | 22,032 | 3.28bp | 8.0h | 52.0% |
| s2.50 · 창72h · 4시간마다 | 693 | −20.50bp | 7.8h | 51.9% |

읽는 법: **문턱을 올리는 게 전부다.** s 1.25 에서 2.50 으로 올리면 거래가 37배 줄고
거래당 총이익이 7배 뛴다. 기본 문턱으로는 1.40bp 라 메이커 수수료조차 못 넘는다.

### 3년 전량 검정 (s=2.50 · 창24h · 1시간마다)

거래 **6,565건** · 1,312일 · 총이익 **5.84bp** · 표준편차 233.2bp · **t=2.03** · 승률 52.1%
95% 신뢰구간 [0.20, 11.48] bp.

| 비용 가정 | 거래당 순이익 | t |
|---|--:|--:|
| 비용 0 | +5.84bp | +2.03 |
| 메이커 왕복 4bp | +1.84bp | +0.64 |
| 테이커 왕복 10bp | −4.16bp | −1.45 |

**총이익은 0 을 겨우 넘지만 순이익은 어떤 비용 가정에서도 유의하지 않다.** 순이익이 t=2 를
넘으려면 왕복비용이 0.08bp 이하여야 하는데 그런 거래소는 없다. 게다가 s=2.50 은 앞의
격자 4개를 보고 고른 값이라 다중검정 보정을 하면 t 문턱은 2.0 보다 높아야 한다.

→ **지금 구성으로는 실거래 불가.** 방향은 "거래를 늘리는 것"이 아니라 **거래당 총이익을
키우는 것**이다. 제일 유력한 실마리: 청산의 68%(4,461/6,565)가 TIMEOUT 이다 —
대부분의 포지션이 회귀하지 못하고 반감기 2배에서 잘린다. OU 반감기가 체계적으로
과소추정되고 있거나(AR(1) 소표본 편의), 애초에 회귀하지 않는 이탈을 잡고 있다.

⚠ 자금조달료가 빠져 있고, 종목별 실비용 대신 균일 비용을 쓴다. 실집행 판단은 이 표만으로 하지 말 것.

## 알아둘 것 (전부 실측으로 물린 것들)

- **1분봉으로 상관을 재면 유동성 순위표가 나온다.** Epps 효과 — 마이크로캡은 1분에 체결이
  없어 수익률이 0 으로 깔린다. 클러스터링은 1시간봉으로 하고 1분봉은 체결·비용용으로만 쓴다.
- **wash_z 회귀엔 2차항이 필수다.** 유동성은 규모에 초선형이라 직선으로 맞추면 BTC(z=2.41)·
  ETH(2.15)가 통째로 "충격이 너무 작다"로 찍혀 탈락한다. 2차항을 넣으면 −0.41·−0.44.
- **Corwin-Schultz 를 비용으로 쓰면 안 된다.** 일봉용 추정량이라 1시간봉에선 10배 넘게
  과대추정한다(BTC 9.7bp vs 실제 0.5~1bp). 유동성 **순위**로만 쓴다.
- **체결은 다음 봉 시가로.** 신호를 만든 봉의 종가로 체결하면 1봉 lookahead 다.
  이걸 고치자 총이익이 3.46 → 2.60bp 로 떨어졌다 — 엣지의 4분의 1이 그 한 줄이었다.
- **RMT 클리핑에서 전 고유값이 잡음이면 전부 눕혀야 한다.** "일부만 잡음일 때만 손댄다"는
  가드를 넣었더니 순수 잡음 행렬이 그대로 통과했다(테스트가 잡았다).
- **k 는 종목 수보다 작아야 한다.** 2023년 초엔 상장이 160종목도 안 돼 `_fit_universe` 가
  조용히 None 을 반환, 초반 8개월이 거래 0건으로 사라졌다 — 예외가 안 나서 눈치채기 어렵다.
- **OU 적합은 벡터화판과 스칼라판이 둘 다 있다.** 백테스트 속도(500종목 루프가 3시간 병목)
  때문인데, 갈리면 백테스트와 라이브가 달라진다. `test_ou_vectorized_matches_scalar` 가
  원소 단위로 대조한다 — **한쪽만 고치지 말 것.**
- **자금조달료(funding)가 데이터에 없다.** 달러중립이라 상당 부분 상쇄되지만 0 은 아니다.
  `--funding-bps-day` 로 스트레스만 걸 수 있다.
- **종목별 실거래비용은 OHLCV 로 원리상 안 나온다.** 호가창이 필요하고 그건 MultiEX 몫이다.
